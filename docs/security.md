# Базовые требования безопасности

## Подписанный журнал операций

При сохранении операции браузер подписывает подтверждение ключом Ed25519 и
шифрует копию данных AES-GCM. Сервер проверяет подпись и связывает запись
с предыдущей через контрольную сумму. Проверка `/vault/integrity` проверяет
порядок, подписи, цепочку и сохранённую вершину журнала; разблокировка
пользовательского ключа для этой проверки не требуется.

Ключ восстановления открывает зашифрованные ключи подписи и копий операций.
Открытые ключи остаются в памяти приложения до обновления страницы или выхода.
Ключ восстановления отличается от пароля аккаунта и резервных кодов 2FA.

Это не сквозное шифрование всей базы: рабочие операции доступны серверу
обычными полями. Проверка журнала не сравнивает все текущие строки `transactions`
с сохранёнными копиями и не даёт независимой гарантии от полного отката базы:
вершина цепочки хранится на том же сервере. Успешная проверка подтверждает
согласованность проверенного журнала в его текущем состоянии.

Import staging хранится в закрытом общем томе API/worker, шифруется AES-GCM
и удаляется после подтверждения либо по TTL. Проверки путей, symlink, прав
доступа и user scoping входят в тесты. Ключи, переход со старых томов и
эксплуатационные ограничения описаны в [deployment.md](deployment.md#import-staging).

- Клиент и его поля недоверенные. Доступ к операциям и счетам проверяется на сервере по authenticated user id.
- Планируем passkey/WebAuthn, резервный passkey и recovery-коды; механизм ещё не реализован.
- HTTPS, httpOnly + Secure + SameSite cookies, CSRF-защита и ограничение попыток.
- Нет долговременных access-токенов в браузерном localStorage.
- PostgreSQL: ограничения прав пользователя БД; в приложении проверка ownership на каждой операции. RLS может стать дополнительным слоем, но не заменой проверок.
- Банковские реквизиты и токены интеграций — только в серверном secret manager/KMS; логирование с редактированием чувствительных данных.
- AI получает только необходимый набор данных, передача третьим сторонам требует явного решения и информирования пользователя.
