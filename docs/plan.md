# План Budgeto

> Статус текущей ветки: реализован web/API MVP-контур с PostgreSQL, auth/session/TOTP, worker-импортом XLSX/CSV/текстовых PDF, CSRF, Vault provenance и версионируемым registry профилей документов. Банковские PDF-профили, OCR и внешний blockchain anchor остаются будущими задачами.

## Рабочая концепция

Budgeto превращает банковскую выписку в проверяемую финансовую историю. Для каждой операции сохраняются источник, способ обработки и история изменений.

Первый клиент — веб-приложение. Tauri добавим после веб-MVP, используя тот же API и интерфейс.

## Архитектура

- Модульный монолит NestJS вместо микросервисов.
- Отдельный worker для импорта, детерминированной классификации документов и тяжёлых фоновых задач.
- PostgreSQL для рабочих данных.
- S3 или MinIO для исходных файлов и snapshots Vault.
- Общие контракты в `packages/contracts`.
- Ошибки импорта имеют стабильные коды и runtime-класс `ImportError` в `packages/contracts`; адаптеры не передают наружу произвольные строки.
- Blockchain только как внешний якорь целостности, без персональных данных в сети.

## Основной сценарий

1. Пользователь загружает XLSX, CSV или текстовый PDF.
2. Система определяет физический формат и выбирает версионируемый встроенный профиль.
3. Пользователь видит сопоставление колонок и preview импорта.
4. Worker парсит файл детерминированным адаптером.
5. Система ищет дубли и сохраняет происхождение каждой операции.
6. Пользователь подтверждает импорт.
7. Импорт становится новой версией истории и фиксируется в журнале.

## Импорт и профили документов

- Ввести единую схему операции: дата, сумма, валюта, направление, продавец, описание, внешний ID.
- Для известных форматов использовать обычные детерминированные парсеры и декларативные профили.
- Профиль содержит только версионируемые правила и ссылки на заранее написанные преобразования; пользовательский JS и произвольные regex не исполняются.
- Табличный профиль может явно задать aliases колонок и delimiter; PDF-профиль явно выбирает single, signed, first или last amount, чтобы неоднозначные суммы не угадывались молча.
- Классификатор считает score по физическому формату и признакам профиля; tie или низкий confidence переводят импорт в ручную проверку.
- Собрать обезличенный набор выписок с разметкой форматов и golden JSON-ожиданиями.
- Небольшой `scikit-learn` классификатор можно добавить после накопления fixtures, но он не должен вычислять суммы, даты и валюты.
- Сканированные PDF явно остаются неподдержанными без OCR.
- Не использовать LLM для вычисления сумм, дат и валют.

## Трассировка и Vault

- Хранить исходный файл, лист, строку и исходные значения для каждой операции.
- Использовать append-only журнал событий: импорт, исправление, объединение, восстановление.
- Добавить Time Machine: просмотр diff, история версий и откат импорта.
- Строить hash-chain или Merkle root для версии Vault.
- После импорта якорить root в блокчейне. В сеть отправлять только хэш, версию и время.

## Безопасность как функциональность

- Security Center: устройства, сессии, доступы и экспорты.
- Automatic Containment: блокировка массового экспорта и read-only режим при подозрительной активности.
- Ролевой доступ к общему Vault без раскрытия всех полей.
- AI остаётся read-only и получает только разрешённую проекцию данных.
- Банковские пароли не храним.
- S3/MinIO закрыт, файлы шифруются, клиент не получает постоянные credentials.

## Порядок работы

1. Canonical schema и доменная модель импорта.
2. Worker с загрузкой, preview и детерминированным parser pipeline.
3. PostgreSQL и сохранение import jobs, transactions и provenance.
4. Первая ML-модель классификации формата.
5. Дубли, подтверждение, rollback и версии Vault.
6. Append-only ledger и проверка целостности.
7. Security Center и Automatic Containment.
8. Blockchain anchor как демонстрационная интеграция.
9. Tauri после стабильного веб-MVP.

## Не делаем на первом этапе

- Микросервисы.
- Полноценные банковские интеграции с хранением паролей.
- LLM-парсинг финансовых значений.
- Публичное хранение транзакций в блокчейне.
- Отдельный desktop-клиент до готовности веб-версии.
